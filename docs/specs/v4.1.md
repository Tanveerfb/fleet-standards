## Goal

Take the nine proposals raised since v4.0.0 (issues #35 to #39, #41 to #44), and bring
`checkpoint` and `relay` in line with how v4 lays the rules out. The owner, 2026-11-27: the

documentation and other management".

**It deliberately does not:** rename or renumber a section; change a rule beyond what a
proposal or a pick asks; re-audit any project.

## New sync checks (`sync-standards` Step 4)

The checks run a to m today. Per `docs/maintainer.md`, each thing an existing project must
do gets one:

- **n. CI runs the gates** — *if the project has a remote, application code and no gates
  workflow,* offer the template for its kind. The owner's yes, as for any workflow.
- **o. Findings from newer rules, read-only** — looks and lists, changes no code: a public
  route or form with no rate limit or length caps (#35); a `next.config` with no `headers()`
  and an `images.remotePatterns` wildcard over a shared host (#38); a legal page whose
  promises `data-model.md` does not record (#37). Each goes in the upgrade report as work
  for the project, with the rule it comes from.

**Check m learns rulesets.** It reads only the older branch-protection API, which answers
404 for a branch guarded by a ruleset (this repository's `main`, since 2026-11-27). It also
reads `repos/<owner>/<repo>/rules/branches/<branch>` and counts `deletion` and
`non_fast_forward` rules there as protection.
